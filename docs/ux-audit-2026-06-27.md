## Executive Summary

AquaFlow Pro is a visually polished swimming team management app with a cohesive dark-teal aesthetic and thoughtful athlete-facing gamification. The athlete side works smoothly — clean login flow, well-structured workout feed, and engaging health/status features. However, two Critical issues undermine confidence: coach login timing failures that expose DB cold-start vulnerability, and a known Chrome crash in the avatar system. The coach dashboard is information-dense but hides critical features behind collapsible sections. Overall, the app is 80% of the way to a polished product; the remaining 20% is about reliability and accessibility, not visual design.

## Findings

### Critical (blocks user task; data loss; security)

#### [C-1] Coach login timeout in Playwright — DB cold-start vulnerability

- **Layer**: Architecture / Interaction
- **Severity**: Critical
- **Surface**: /login (coach flow)
- **Viewport**: 1440×900
- **Persona**: Swimming Coach

**Reproduce**:
1. Navigate to https://sw.sportsflow.best/login
2. Select "教练" role tab
3. Enter username: testcoach
4. Enter password: password123
5. Click login button
6. Observe: no redirect within 15 seconds

**Observed**: Login API returns 200 OK with session cookie, but `router.push("/dashboard")` redirect doesn't complete within 15s timeout in Playwright. The login form has retry logic (up to 5 attempts with exponential backoff: 1.5s, 3s, 4.5s...) which means a cold DB start could take 30s+.

**Expected**: Login should complete within 3 seconds on a warm DB, and gracefully handle cold starts with clear progress indication.

**Evidence**:
- `.jez/audit-evidence/2026-06-27/` — coach login screenshots (timeout states)
- API curl test: `POST /api/auth/login` returns `{"success":true,"user":{"name":"Test Coach","role":"coach"}}` — API works
- Playwright error context shows login page still rendered after 15s timeout
- `components/athlete/LoginForm.tsx:36-123` — retry loop with up to 5 attempts

**Suspected location**: `components/athlete/LoginForm.tsx:126` — `redirectAfterLogin` uses `router.push()` which may conflict with Next.js App Router navigation during loading state

**Smallest possible patch**: In `redirectAfterLogin`, add `router.refresh()` before `router.push()` to force revalidation of server-side auth state. Also add a visible timeout indicator showing current retry attempt number so users know the system is working, not stuck.

#### [C-2] AvatarRenderer disabled due to Chrome crash — no placeholder for equipped avatar

- **Layer**: Architecture / Visual
- **Severity**: Critical
- **Surface**: /workout (athlete header)
- **Viewport**: 1440×900, 375px
- **Persona**: Athlete

**Reproduce**:

Athletes who purchased avatar items in the shop see only a generic UserCircle2 icon instead of their equipped avatar.

**Expected**: A working avatar display, or at minimum a graceful placeholder that doesn't lose the gamification value.

**Evidence**:

**Suspected location**: `components/athlete/AvatarRenderer.tsx` (file exists but not imported)

**Smallest possible patch**: If the crash is from canvas/SVG complexity, implement a simpler fallback renderer using static PNG sprites or CSS-based avatar. Show the avatar shop items as static images until the dynamic renderer is fixed. Add a "Coming Soon" badge if no fallback is feasible.

### High (confusion, friction, trust damage; console warning; layout collapse)

#### [H-1] Mobile nav lacks Escape key handler and focus trap

- **Layer**: Interaction / Architecture
- **Severity**: High
- **Surface**: All coach pages (mobile viewport)
- **Viewport**: 375px, 768px
- **Persona**: Swimming Coach (poolside, mobile)

**Reproduce**:
1. Open coach dashboard at 375px viewport
2. Click hamburger menu icon
3. Press Escape key

**Observed**: The mobile nav overlay (`MobileNav.tsx`) does not close on Escape. It also lacks a focus trap — Tab key can move focus to elements behind the overlay.

**Expected**: Escape should close the mobile nav. Focus should be trapped within the overlay when open.

**Evidence**:
- `components/layout/MobileNav.tsx:46-115` — no onKeyDown handler for Escape, no focus trap
- The overlay has `role="dialog" aria-modal="true"` but doesn't enforce focus trapping

**Smallest possible patch**: Add `useEffect` with `keydown` listener for Escape → `setIsOpen(false)`. Use `focus-trap-react` or implement a simple focus boundary loop. Touches 1 file, ~15 lines.

#### [H-3] Weekly plan day buttons use 8px font — unreadable at mobile viewport

- **Layer**: Visual
- **Severity**: High
- **Surface**: /workout (training week picker)
- **Viewport**: 375px
- **Persona**: Athlete

**Reproduce**:
1. Open athlete workout page at 375px viewport

**Smallest possible patch**: Change `text-[8px]` to `text-[10px]` on both lines. Alternatively, remove the label entirely at 375px and show only the colored dot indicator. Touches 1 file, 2 lines.

#### [H-4] Login retry attempt text not internationalized

- **Layer**: Interaction
- **Severity**: High
- **Surface**: /login
- **Viewport**: All
- **Persona**: Swimming Coach (Chinese-speaking)

**Reproduce**:
1. Navigate to login page with slow network
2. Submit login form
3. Observe loading text during retry

**Observed**: The retry loading text shows `Connecting... attempt X/5` and `Connecting to server...` in hardcoded English (`LoginForm.tsx:235`), despite the app being bilingual. A Chinese-speaking coach sees English text during the most stressful part of the login flow.

**Expected**: Retry text should use the bilingual dictionary (`t.common.loggingIn`, etc.).

**Smallest possible patch**: Add `loginRetrying` and `loginConnecting` to the dictionary, use `t.common.loginRetrying` in LoginForm.tsx:235. Touches 2 files, ~4 lines.

#### [M-3] axe-core CSP block — Content-Security-Policy prevents runtime accessibility auditing

- **Layer**: Architecture
- **Severity**: Medium
- **Surface**: All pages
- **Persona**: All

**Observed**: The CSP header (`script-src 'self' 'unsafe-inline' 'unsafe-eval'`) blocks external scripts like axe-core CDN. While this is good for security, it means automated a11y auditing cannot inject axe-core at runtime. Manual a11y audit was performed instead.

**Smallest possible patch**: For testing environments, add `https://cdnjs.cloudflare.com` to script-src in dev mode only. Or bundle axe-core as a dependency.

- **Layer**: Accessibility
- **Severity**: Medium
- **Surface**: /dashboard
- **Persona**: Keyboard-only Coach

**Observed**: The athlete workout page has a proper skip navigation link (`app/(athlete)/workout/page.tsx:410-414`), but the coach dashboard (`app/(driver)/dashboard/page.tsx`) has no equivalent. A keyboard-only coach user must tab through the entire sidebar before reaching content.

**Smallest possible patch**: Add a skip link identical to the athlete version at the top of the coach dashboard. Touches 1 file, ~8 lines.

#### [M-5] Sidebar logout uses window.location.href instead of router.push

- **Layer**: Architecture
- **Severity**: Medium
- **Surface**: Coach sidebar
- **Persona**: Swimming Coach

**Smallest possible patch**: Replace `window.location.href` with `router.push()` in both Sidebar and MobileNav. Touches 2 files, 2 lines.

## What Works Well

Positive findings — patterns to preserve and replicate:

1. **Skeleton loading states**: The athlete workout page has comprehensive skeleton screens (header, calendar, training card, stats, bottom bar). This is production-grade loading UX.
2. **Gamification integration**: XP bar, level badge, and shop system create meaningful engagement without being distracting.
3. **Error handling**: Sync error state shows a beautiful glass-panel with retry and logout options. Login form has 5-retry exponential backoff with clear retry counter.
4. **Bilingual support**: The app handles Chinese/English switching seamlessly with `useLanguage()` throughout.
5. **Date navigation**: The weekly calendar with left/right arrows and "back to this week" button is intuitive.
6. **Skip navigation**: Athlete page has a proper sr-only skip link (coach page should match).
7. **Responsive design**: The athlete page uses `max-w-2xl` centering that works well across viewports.
8. **Avatar crash mitigation**: The team disabled the crashing component and replaced it with a functional fallback — this is the right production call even if the placeholder is generic.

## Hold this in your hands

This app feels like it was built by people who swim. The weekly calendar is the right primitive — coaches think in weeks, not days, and the arrow-navigation with "back to this week" button respects that rhythm. The athlete side is genuinely delightful: gamification, health status, and targeted feedback all serve the core loop of "see what's assigned, do it, report back." What keeps it from being something I'd hand to a coach without caveats is reliability at the margins. The login timeout, the disabled avatar, the hidden stats panel — these are the friction points that compound over 300 poolside logins a month. Fix those five items and this stops being "an app we use because we have to" and becomes "the thing I open before practice every day."
